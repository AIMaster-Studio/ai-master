# 实验记录与分析（2026-09-15）

本次共两个实验。每个都记录**设计、过程、结果、结论**，并明确写出**局限**。

---

## 实验一：本机哈希嵌入的召回代价到底有多大？

### 为什么做这个实验

「默认嵌入是词面重合、不是语义检索，同义改写会漏召回」是本项目**主动对外声称**的一条边界。
但在本实验之前，它只有定性描述。读者读到「会漏召回」，无法判断是「偶尔漏一个」
还是「基本没法用」—— 这两种情况的应对方式完全不同（前者可以接受，后者必须换嵌入模型）。

**一个说不清代价的边界，等于没写。**

### 设计

| 要素 | 设定 |
| --- | --- |
| 语料 | 仓库自带课程内容灌成的知识库：74 篇文档 → 93 个可引用块 |
| 索引 | `local-hash-256` 嵌入 + `sqlite-vec` 后端，v1 |
| 自变量 | 查询的**表述方式**：A 原词版（直接用课程原文用词）／B 改写版（换同义说法，刻意避开原词） |
| 因变量 | Top-3 命中里是否出现期望章节的块（用 `source` 字段判定） |
| 控制 | 同一知识库、同一索引版本、同一 k、同一次运行 |
| 样本 | 8 道题，覆盖 chapter_01/02/03/05/08/10 |

**判据说明**：用「Top-3 是否包含期望章节」而不是「是否命中某个特定块」，
是因为同一章节有多个块，命中任意一个都算检索成功。这是更宽松、也更贴近实用的判据。

### 过程

```bash
node scripts/experiment_retrieval_recall.js
```

脚本可复现，原始结果写入 `scripts/experiment_retrieval_recall.results.json`。

### 结果

| 题 | 期望章节 | 原词 Top-3 | 改写 Top-3 | 改写版实际 Top-1 |
| --- | --- | --- | --- | --- |
| E1 | chapter_01 | 命中 | 命中 | chapter_08 |
| E2 | chapter_01 | 命中 | **未命中** | chapter_08 |
| E3 | chapter_01 | **未命中** | 命中 | chapter_01 |
| E4 | chapter_02 | 命中 | **未命中** | chapter_03 |
| E5 | chapter_03 | 命中 | 命中 | chapter_03 |
| E6 | chapter_05 | 命中 | 命中 | chapter_05 |
| E7 | chapter_08 | 命中 | **未命中** | chapter_03 |
| E8 | chapter_10 | 命中 | **未命中** | chapter_01 |

| 指标 | 原词版 | 改写版 |
| --- | --- | --- |
| Top-3 命中率 | **7/8（88%）** | **4/8（50%）** |
| Top-1 命中率 | 7/8（88%） | 3/8（38%） |

### 结论

1. **这条边界是真实的，而且代价可量化**：换成同义说法提问，Top-3 召回率从 88% 掉到 50%，
   Top-1 从 88% 掉到 38%。也就是说**用学习者自己的话提问，约一半的题目检索不到正确章节**。

2. **但「词面重合」并不等于「不能用」**：原词版 88% 的命中率说明，
   当查询词与课程用词接近时（例如学习者刚读完本节、用的是同一批术语），检索是有效的。
   所以正确的表述不是「检索不可用」，而是**「用课程用词提问有效，用自己的话提问约一半失效」**。
   这比原来那句笼统的「会漏召回」更有用 —— 它直接给出了可操作建议。

3. **失败方向是「跑到别的章节」而不是「什么都搜不到」**：改写版 4 次未命中里，
   实际 Top-1 分别落到 chapter_08 / chapter_08 / chapter_03 / chapter_01。
   **没有任何一次是空结果。** 这一点比命中率更值得警惕：
   学习者看到的是「有结果、看起来也相关」，不会意识到找错了地方。
   这与本项目一贯强调的「失败要可见」相冲突 —— 检索失败在这里是**静默的**。

4. **E3 出现了反向结果**（原词未命中、改写命中），说明这个指标有噪声，
   8 道题的样本量不足以支撑更细的结论。

### 局限

- **样本极小**：8 道题、单次运行，没有重复试验，没有置信区间。上述百分比只能当量级参考，
  不能当作精确性能指标。
- **改写版由我编写**，我已知晓期望章节，存在无意的偏向。真实学习者的改写会更分散。
- 只测了 `local-hash-256` 一种嵌入。配了远程嵌入模型后结论**不适用**。
- 只测中文。跨语言（中英混问）完全没测，而那是词面重合最吃亏的场景。
- 判据用「期望章节」是我人工指定的，本身就是一种主观标注。

### 由本实验直接得出的改进项

**检索失败目前是静默的**（见结论 3）。这是一个真实缺陷：
用户看到有结果就不会怀疑。已记录为待办，候选方案是在结果里显示相似度阈值提示 ——
注意**不能**简单地说「低于 X 就不显示」，因为相似度分布随嵌入器变化，
写死阈值会变成新的误导。

## 实验二：界面视图的渲染验证（含截图）

### 设计

用无头 Chrome 实际加载页面并截图，验证三个新视图在真实浏览器里能渲染出预期内容 ——
而不是只靠读代码或跑 DOM 断言推断。

**顺带发现的必要前置**：三个新视图此前**只能通过点击侧栏按钮进入**，
既不能直接链接，刷新也会回到默认视图，无头浏览器更是无法到达。
为此给视图切换加了 URL hash 路由（`#memory` / `#rag` / `#research`），
这既是可用性改进，也是本实验能执行的前提。

### 过程

```bash
chrome --headless=new --virtual-time-budget=9000 --window-size=1440,1150 \
       --screenshot=<view>.png "http://127.0.0.1:8788/learning-center/#<view>"
```

### 结果

截图见 `docs/ican/evidence/screenshots/`：

| 文件 | 内容 |
| --- | --- |
| `learn.png` | 今日学习（新访客的空状态） |
| `memory.png` | 学习记忆（L1/L2/L3 + 记忆图谱） |
| `rag.png` | 知识库（引擎状态、索引后端、知识库列表） |
| `research.png` | 深度研究（工具清单、提问表单） |

人工核对 `rag.png` 确认渲染正确：4 个引擎状态分别为 ready / needs-config /
not-implemented / not-implemented，2 个索引后端均 ready，
知识库显示「74 篇文档 · 3 个索引版本 · 当前 v3」，
且「本机哈希嵌入不是语义检索」的提示位于页面最显眼处。

### 过程中发现的两个真实缺陷

1. **第一次截图全部得到同一张错误页**（`ERR_CONNECTION_REFUSED`）。
   原因：后台服务进程已退出，而截图命令**仍然返回退出码 0**。
   四张图的字节数完全相同（25408）才暴露了问题。
   **教训**：命令成功 ≠ 产物正确。只检查「文件生成了没有」会漏掉这类问题，
   必须校验产物之间是否存在合理差异。

2. **记忆视图的证据面板会说谎**。核对数据时发现：模型未配置时，
   服务端**仍然检索了课程证据**（`grounding.evidenceCount > 0`），
   但因为没走模型，`result.evidence` 为空。
   而面板在 `evidence` 为空时统一显示「本次没有可引用的课程证据」——
   这会让人以为课程库是空的，从而去修一个并不存在的问题。
   已修正为区分两种情况：未走模型 → 「本地规则不引用证据（本次实际检索到 N 条，但没有送入模型）」。

### 结论

界面在真实浏览器中渲染正确，三个新视图可用。
但**实验的价值主要来自过程而非结论**：两个缺陷都不是靠「跑通了」发现的，
而是靠**核对产物**（字节数、数据字段）发现的。

### 局限

- 只验证了 Chrome 一种浏览器、1440×1150 一种视口。移动端布局未验证。
- 截图是**新访客的空状态**（无 cookie），因此看不到有数据时的界面。
- 无头渲染不覆盖交互行为（点击、表单提交）；那部分由契约测试与接口测试覆盖。

---

## 两个实验共同的局限

- 都是**本机单次运行**，没有重复、没有并发、没有长时运行。
- 都不能用于推断真实用户的学习效果 —— 见 `facts-and-limits.md` 的证据层级一节。
- 实验一的结果与**具体语料和嵌入器绑定**；换课程库或换嵌入模型必须重跑。
