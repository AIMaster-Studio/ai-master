# 评委问答

回答以当前本机原型为准。括号中的证据路径供答辩者定位，不必口头全部报出。

## 一、创新与竞争差异

**问：你们到底创新在哪里？**

答：我们把学习后的自己讲解、独立客观测验、失败修订和持久复习记录组织成一条流程。讲解达标与测验至少 75% 同时满足才记录通关。贡献是交互与教学任务的工程实现，目前不声称提出新模型或证明一种新教育理论。

**追问：费曼学习法和测验早就有了，拼在一起也算创新？**

答：这些方法已有研究和产品实践，我们不主张拥有方法本身。我们需要证明的是在具体 AI 入门场景中，任务设计、可追踪反馈和操作成本是否优于可比较的方案。当前能展示实现，竞争优势仍需用户与效果研究支持。

**追问：为什么不用通用聊天助手？**

答：通用助手很适合解释问题。这里额外提供固定任务范围、独立答案判定和连续记录。但如果学生用普通助手同样方便、效果相当，我们就需要重新评估差异价值，不能只靠界面风格证明优势。

## 二、教育理论与学习效果

**问：五十七个节点的认知层级从哪里来？**

答：依据修订版 Bloom 分类，逐节点按要求学习者完成的行为来标注。例如 BPE 做合并演算，RAG 评估要区分检索与回答问题，产品介绍节点仅要求理解。标注是团队设计建议，不是教师一致性验证或学习成果。（`knowledge-cognitive-map.json`）

**追问：有没有证明提高学习成绩？**

答：目前没有本项目的因果效果数据。相关检索练习与分散练习文献支持研究动机，不能当成本产品的效果。我们的研究计划比较相同内容与学习时间下的迁移任务和延迟测验，预先确定指标与分析方法。

**追问：点亮星球就代表掌握了吗？**

答：不代表。通关只记录本次规则下的表现。需要独立平行题、延迟测验和实际任务来检验能否保持与迁移，也应单独记录复习失败。

## 三、技术实现与评分可靠性

**问：后端是否真的存在？**

答：本次增加的是 Node.js 本机服务与 SQLite 持久化，不是旧宣传中的私有 Flask 完整版。可以用实际接口、刷新恢复和导出记录核查。静态版仍能看课程，但静态托管不提供这个本机服务。

**追问：评分是不是只看字数和关键词？**

答：本地讲解检查是启发式规则，存在误判与漏判。模型可配置为结构化复评，但它也会犯错。因此客观题另按预设标答独立判分，模型不决定标答或直接写入通关结果。双重条件降低部分问题，不保证理解判断绝对正确。

**追问：抄答案、反复刷题或提示注入怎么办？**

答：本地规则能拦截部分重复、空泛输入，服务端负责通关条件和提交状态检查；这些都不能证明身份或防止外部代答。当前是练习工具，题库规模也有限，不作为高风险考试。模型返回内容须被当作不可信数据解析，客观评分不接受其指令。

**追问：模型调用失败会不会暗中给一个假结果？**

答：失败或未配置时明确展示本地练习或降级状态，不称为模型评审。现场可断开模型配置验证；不应为了演示流畅伪造模型输出。

## 四、产品体验与角色设计

**问：鲸鱼娘是否只是装饰？**

答：目前用于学习状态反馈和陪伴呈现，是否提高坚持度仍是待测假设。学习者要能在动效之外清楚看到任务、分数和下一步，不依赖角色动作理解关键结论。

**追问：服装与大学课堂是否相符？**

答：这是原有第三方形象，本轮按要求保留全部形象和动作。不同课堂接受度可能不同，应通过学生与教师访谈了解干扰和适配问题；我们没有校方认可该形象的证明，也不会把审美偏好当作教学收益。

**追问：移动端或低端电脑能顺畅运行吗？**

答：仅能报告实际验收过的浏览器与视口，浏览器模拟手机尺寸不能证明低端真机帧率、内存或耗电。3D 与视频资产带来额外负载，后续需在明确型号的设备上测试。

## 五、版权与第三方依赖

**问：鲸鱼娘和九十七个动作是你们原创吗？**

答：不是团队原创声明。素材来自仓库纳入的 dsh-pet，上游 README 描述 97 个动作。本地实测有 97 个 GIF、100 个 WebM，文件数与动作口径不能混用。我们保留原资源和署名，不把集成工作说成资产原创。

**追问：MIT 不是可以商用吗？**

答：需要区分代码和素材。上游 LICENSE 是 MIT，但 README 明确写“代码：MIT；素材（动画/提示词/源视频）：允许开源使用，禁止商用”。因此不能把代码许可扩大到这些素材的商用权。商业使用前需要权利方明确授权，并核实角色、字体及其他底层权利。

**追问：参赛、宣传、公开演示是否都已获授权？**

答：目前核实的是许可文本，并没有针对所有使用场景的书面确认。赛事宣传、赞助展示、公开分发是否落入限制，需要结合比赛安排向权利方确认。我们不会用“开源”替代完整权利核查。

## 六、商业与运营

**问：谁会付费？**

答：目前优先验证高校 AI 入门实践课教师是否需要任务与反馈工具，课程组织方是否愿意承担费用；学生自主练习是另一假设。还没有合同、营收或付费转化数据。

**追问：成本和利润是多少？**

答：现在只能列成本结构：模型输入输出用量、服务资源、课程审校、教师支持和授权成本。使用本地练习时不产生模型调用费，但内容与支持成本仍存在。单价、调用频率和续用意愿要实测后才能算利润。

**追问：有多少活跃用户，留存怎么样？**

答：当前没有可核实的真实活跃用户与留存报告。演示档案、自己测试和浏览次数不计作真实活跃用户。后续先约定活跃的行为定义，再在取得同意的试点中记录。

## 七、团队、赛道与证据可信度

**问：为什么报创新赛道，学校是否确认？**

答：用户已经选择创新赛道，当前材料按这个方向组织。现有仓库没有校方正式确认材料，因此不能说已得到学校审核或推荐。报名资格和最终赛道以赛事与学校实际文件为准。

**追问：使用 AI 写代码后，团队贡献怎么证明？**

答：如实披露 AI 辅助，展示需求决策、任务设计、实现差异、测试和问题处理。提交记录可证明改动过程的一部分，不能单独证明所有代码原创、独立完成或教学效果。

**追问：此前说有私有完整版、专家打分很高，这些能查吗？**

答：当前材料没有可核实的私有 Flask 完整版，也没有真实专家评分证明。此前模拟问答中的设定、评分和承诺不能转成项目事实。本次应以实际仓库、运行记录和真实第三方材料回答。

## 追加质疑

**问：全部课程内容都准确完整吗？**

答：不能这样说。第七章首节点正文为空，第十章主要是产品介绍与跳转；部分历史课程中的模型规模、性能数字和工具配置需要更新核查。认知地图逐节点标出内容状态，新增核心任务应单独审校，不能把整套旧课程当成权威题库。

**问：为什么不给一个试验样本数和预期提升百分比？**

答：试点人数由可用性问题是否充分暴露与资源决定；正式效果试验应按主要指标、可接受误差与功效分析确定样本数。没有先验依据时，随意写人数和提升百分比会制造虚假确定性。

**问：数据存在哪里，会发给模型吗？**

答：进度由本机服务保存。开启远程模型复评时，讲解与评价所需的上下文会发送给所配置服务商，因此不能笼统宣称所有数据永不出机。试点前应核对实际发送字段、告知参与者并避免敏感信息。当前不声称云同步、跨设备恢复或企业级隐私合规。

**问：真正下一步是什么？**

答：先完成内容事实审校和素材授权核查，再做真实学生可用性试点；在这些条件具备后，用预先定义的教育效果试验判断是否值得扩大。每一步都设停止或修订条件。
