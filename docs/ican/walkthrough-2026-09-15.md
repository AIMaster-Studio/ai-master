# 小白访站走查（10 轮）· 2026-09-15

## ⚠️ 先说清楚这是什么，不是什么

**这是启发式走查（heuristic walkthrough），不是用户研究。**

| 是 | 不是 |
| --- | --- |
| 由我扮演「没读过 README 的人」，走 10 条自然路径 | 真实用户 |
| 每轮开**全新会话**（无 cookie = 完全遗忘记忆） | 真实的新用户样本 |
| 记录每一步**实际拿到什么**（HTTP 状态 + 响应字段 + 文案） | 主观满意度 |
| 回答「按最自然的路径走会撞到什么」 | 回答「用户会不会满意、会不会留下、学到了什么」 |

**它的根本局限**：路径是我写的，所以我只会撞到我预想到的问题。真实用户会做我没预想到的事 ——
而这恰恰是最有价值的那部分。任何把本报告当作「用户验证」的用法都是错的。

脚本：`scripts/walkthrough_newbie.js`（可复现）；原始结果：`scripts/walkthrough_newbie.results.json`。

## 二、十轮感悟

### 1. 第 3、4 轮：被拦住，但拦得讲道理

想跳过讲解直接做题，得到的是 409 加一句**可执行的话**——「请先生成包含这个任务的学习计划」，
而不是「403 Forbidden」。第 4 轮想跳到最后一章，也是同一句。
这两轮没有摩擦感，因为**拦截理由本身就在指路**。

这是本项目的做法里我最认可的一处：**挡住你的同时告诉你该做什么**。

### 2. 第 7 轮：一处把「可选」说成「不可用」的误导（已修）

`explain`（讲解复评）在未配置模型时被标成 `needs-config`。但事实是：
**它没配模型也能用**，只是退到本地规则筛查。

一个没读过文档的人看到 `needs-config`，最自然的反应是「那这个功能现在不能用」，
于是**直接放弃一个本来可用的功能**。这不是措辞问题，是功能可用性被错误地隐藏了。

**已修**：`explain` 改为 `ready`，并加 `modelOptional` + `modelNote`
说明「未配置时走本地规则；配置后追加模型复评」。
`research` 保持 `needs-config`——它**确实**必须有模型，没有本地降级路径。
区别对待的依据是「有没有降级路径」，不是「用不用模型」。

### 3. 第 9 轮：跑题被当成了「没讲全」（已修）

这是本轮走查最有价值的一条。

小白写了一段跟课程毫无关系的运动会作文，得到的反馈是：

> 待补充：token 与文本编码；待补充：基于上下文预测；待补充：幻觉与事实核验

**从头到尾没有一个字告诉他「你写的和本节无关」。** 他会理解为「我讲得不够全」，
然后去补几个关键词 —— 而正确做法是**换主题重写**。这是两种完全不同的行动。

系统其实**知道**：一个关键概念都没命中，与「漏讲了两个」是完全不同的信号，
但两者被压成了同一句「待补充」。

**已修**：新增 `offTopic` 判定（有效内容 ≥100 字且命中 0 个关键概念），
反馈改为先明说「这段讲解没有覆盖本节要求的任何关键概念，看起来写的是别的内容。
请先确认你讲解的是「大模型如何生成回答」，再围绕它重写」，
追问也相应换成「请先用一句话说明本节的主题是什么」。
同时加了反向测试：只漏讲部分概念时**不得**被判成跑题。

### 4. 第 6 轮：`GET /api/rag/search` 返回 405

界面上用的是 POST，所以真实用户不会撞到。但它暴露一个接口设计问题：
**检索是只读操作，却只接受 POST。** 一个想直接拼 URL 试一下的人会拿到 405。

当时记为待办，理由是要动前端调用与契约测试、收益只是「URL 可直接访问」。

**已修（2026-09-15 后续轮次）**：改为 GET 与 POST 共用同一份参数校验与失败语义，
同参数下结果一致；前端继续用 POST，未受影响。顺带修掉一个同源问题：
空 `query` 原先会一路抛到 500「服务暂时出错」，现在返回 400 并说明缺什么 ——
**调用方参数错误不该伪装成服务端故障**。

边界照旧标注：GET 的查询词会进 URL（代理、隧道与访问日志可见），长查询仍应用 POST；
GET 不提供任何 POST 没有的能力。这些由 `tests/grounding.test.js` 的
「search is read-only」用例钉住，不是靠这段文字保证。

### 5. 第 5 轮：空状态是诚实的，但没给出下一步

新访客打开「学习记忆」，看到的是：L1 事件 0、5 个记忆面全空、L3「（未生成）」。
文案已经解释了「空白不代表你没有学习记录」「L3 按需生成」——**这比显示成空白好得多**。

但**没有任何入口指向「去做什么会产生记录」**。小白看完这一页会退出去，
不知道该去哪里。这是可用性缺口，不是诚实性问题。

**已修（2026-09-15 第二轮）**，同时发现这条记录本身有两处不准：

- 「知识库空状态」当时并没有这个问题 —— 该视图早就带「用仓库自带课程内容建立课程知识库」
  按钮。这一行把两个视图合并写，把已经可用的一侧也算进了缺口。
- 记忆视图的空文案**其实永远不会渲染**。空分支写的是 `surfaces.length ? 面卡片 : 空文案`，
  而 `surfaces` 是**全部已登记的记忆面**（无活动时 `events` 为 0），长度恒等于面数、永不为 0。
  所以第 5 轮看到的「5 个面全空」才是真实渲染结果，那句空文案是一段死代码。
  修法是改用 `l1Total` 判空，并在空状态里给出「去完成一次讲解」入口。
- 顺带收紧：零事件时不再提供「按当前 L2 事实生成」按钮。在零事件上生成的 L3
  是一份「讲解提交 0 次、通过率 0%」的文件 —— 它如实，但会被读成「学得不好」，
  而实际情况是「还没开始」。这是同一类问题的另一面：**把没有数据表达成 0 分**。
  当时的处置只在界面上绕开，**根因在服务端**：`curate` 的 `pct(0, 0)` 返回 0。
  该根因已修（比例在无基数时返回 `null`，渲染为「无数据」），
  因此服务端直接产出的 L2/L3 文件本身也不再写「通过率 0%」——
  见 `server/memory/store.js` 与 `tests/memory.test.js` 的
  「absence is reported as "no data", never as a 0% score」。

### 6. 第 2 轮：有 7 个模块，但没告诉他从哪开始

课程列表给了 7 个模块，但没有「建议从第一个开始」的引导。
本项目其实**已经有**基于诊断的学习航线功能，只是在这一轮路径里没被触发。

## 三、汇总与优化（10 轮 → 4 项，另 1 项为第二轮补充发现）

| # | 问题 | 类型 | 处置 |
| --- | --- | --- | --- |
| 1 | `explain` 被标成 `needs-config`，把可用功能说成不可用 | **误导** | **已修**（`ready` + `modelOptional` + 说明） |
| 2 | 跑题讲解被当作「没讲全」，未指出跑题 | **误导** | **已修**（`offTopic` 判定 + 明确文案 + 反向测试） |
| 3 | 记忆视图空状态无「下一步」入口（原写作「记忆/知识库」，见 §二.5 的更正） | 可用性 | **已修**（改用 `l1Total` 判空 + 去学习入口 + 零事件不给 L3 生成） |
| 4 | `GET /api/rag/search` 返回 405 | 接口设计 | **已修**（GET 与 POST 等价 + 缺 query 由 500 改 400） |
| 5 | 「显式偏好」有写入接口 `/api/memory/preference`，但界面上没有写入入口 | 可用性 | 待办（2026-09-15 第二轮补充发现） |

第 5 项与待办 1/2/3 是同一类问题的第 4 次出现：**接口有了、页面没有**。
它比前几次更别扭一点 —— 页面上写着「偏好只能显式写入」，却没有任何地方可以写。

**两项「误导」都指向同一个模式**：系统内部其实分得清两种情况，
但在对外表达时把它们**压成了同一句话**——于是可用被显示成不可用、
跑题被显示成不完整。

这是比「文案不好」严重得多的问题：它让用户对系统状态产生错误判断，
并且**不会报错**。本项目一贯强调「失败要可见」，这两处恰恰是失败**不可见**。

## 四、这份走查不能证明什么

- **不能当作用户研究**。样本是我一个人扮演的，路径是我写的，结论有确认偏差。
- 只覆盖 **HTTP 层与接口语义**，没有覆盖真实点击、表单、移动端布局、无障碍。
- 没有测「用户会不会满意」，只测了「会不会撞到错误的东西」。
- 10 轮 × 3~4 步 = 约 30 次交互，样本极小，不能支撑任何统计结论。
- 待办里的「空状态入口」**已经改掉，但没有验证过改完是否真的更好** —— 它只是基于走查的判断，
  不是结论。本轮能证明的只有「空分支原先不可达」这一条代码事实。
- 「GET 检索」已修，但被验证的只是**接口自洽**（GET 与 POST 同结果、缺参数返回 400），
  不是「用户因此更满意」—— 本次仍未做过真实用户点击与满意度测量。
