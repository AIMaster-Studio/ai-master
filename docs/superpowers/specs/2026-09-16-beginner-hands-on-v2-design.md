# AI Master 新手引导与全节点动手实践设计

## 结论

本次改造把 AI Master 从“能看、能讲、能测”补成“知道从哪开始并能留下可验收成果”的学习产品。实现以远端 `feat/beginner-and-hands-on` 的第一版为基础，但不把“10 章有页面”误当成“57 个知识节点已覆盖”：最终验收以 `knowledge-universe.json` 中 57 个节点全部映射到至少一道实践题为准。

## 背景与现状

- 课程当前包含 10 章、57 个知识节点。
- 第一版已有 20 道跨节点实践题，每章 2 道；按节点标题精确核对，只覆盖 38/57 个节点。
- 第一版新手页只列出豆包、扣子、阿里云百炼和 AI Master，缺少需求中明确点名的 ChatGPT、文心千帆，也没有真正的图解。
- 第一版只把新页面加入全局导航，章节知识卡片没有直达对应实践的入口。
- 第一版验证只检查页面是否存在，没有检查实践字段、57 节点覆盖或工具卡完整性。
- 隔离工作区基线为 118/118 Node 测试通过；前端验证为 30 页、7 资产、356 条内部链接、10 个星系、57 个节点通过。
- `package.json` 与 `package-lock.json` 的可选依赖 `sqlite-vec` 不同步，导致 `npm ci` 失败；现有测试不依赖新安装即可运行。该锁文件问题属于独立维护项，不在本次内容功能中顺手改动。

## 目标

1. 57 个课程节点全部能找到与其对应的可执行实践。
2. 每道实践至少明确：任务目标、从哪开始、操作步骤、预期成果、验收信号、预计用时和安全/成本提醒。
3. 每个章节页的每张知识卡都提供直达对应实践的入口，并保留原有实验入口。
4. 新手页覆盖豆包、ChatGPT、文心千帆、扣子、阿里云百炼和 AI Master；用原创图解说明适用场景、核心功能、上手路径与门槛。
5. 提示词协作规则沉淀为长期助手偏好：用户只需给“场景 + 最终目的”，助手自动补全需求、角色、规则和输出格式，并产出通用版与高阶版。
6. 借鉴高星开源课程的教学结构，但不复制其代码、文案、图片、页面布局或品牌资产，满足后续软件著作权材料的独立创作要求。

## 非目标

- 不在本轮证明教育效果或学习成绩提升。
- 不接入新的云端模型、账号体系、付费 API 或部署服务。
- 不把 57 道实践全部升级成大型项目；允许多个节点共用一项综合实践，但每个节点必须有明确映射和可见入口。
- 不重写十章课程正文，不顺手处理与本目标无关的历史事实审校问题。
- 不使用第三方平台 Logo、截图或课程插图；图解全部由本项目自行绘制。

## 教学结构

从高星开源课程中只提炼四个抽象模式：

1. 概念学习与动手构建分轨呈现。
2. 每课明确学习目标、环境入口、任务、验收和延伸方向。
3. 为新手提供零号准备页，先解决工具与环境选择。
4. 练习必须产生可观察成果，而不是只要求“体验一下”。

这些模式重新按 AI Master 的“讲解通关 + 证据留存”理念实现。任何外部仓库的句子、代码、插图和视觉布局均不进入交付物。

## 数据设计

继续使用 `frontend/data/hands-on-tasks.json` 作为实践唯一数据源，避免新增第二份互相漂移的课程目录。

### 章节结构

每章保留：

- `chapterId`：1–10 的整数。
- `title`：必须与 `knowledge-universe.json` 的章节名称一致。
- `tasks`：本章完整实践题数组。

### 实践题结构

每道题必须包含：

- `id`：全局唯一，如 `ch3-t2`。
- `title`：以可观察动作为中心，不用“了解”“熟悉”作标题。
- `goal`：学习者完成后能证明什么。
- `whereToStart`：本项目相对入口或官方外部入口；不得只写工具名。
- `steps`：至少 3 个有顺序的操作步骤。
- `expected`：可展示或可核对的成果。
- `antiCheat`：防止用无关产物冒充完成的判据。
- `tools`：所需工具列表。
- `minutes`：正整数预计用时。
- `kind`：省略时为 `knowledge-node`；唯一允许的 `chapter-extension` 是 `ch10-t1` 与 `ch10-t2`，用于保留不隶属现有三项第 10 章权威产品节点的章节拓展实践。
- `knowledgePoints`：`knowledge-node` 题必须逐字使用课程节点标题；一个节点可映射到一项综合实践。`chapter-extension` 题必须为 `[]`，不参与 57 节点映射。
- `verifyState`：入口或事实的核实状态与日期；无法联网核实的项目必须如实标注。

### 覆盖规则

- `knowledge-universe.json` 的 57 个 `(chapter, title)` 是权威集合。
- 每个权威节点必须在同章至少一项任务的 `knowledgePoints` 中出现。
- 不允许不存在于权威集合的标签，不允许跨章冒领节点。
- 允许一个任务覆盖多个相关节点，也允许一个节点被多项任务覆盖。
- `ch10-t1`（提示注入验证）和 `ch10-t2`（能力边界答辩）是唯一的章节拓展题：保留其完整完成合同与稳定 ID，但不以空标签凑覆盖，实践页将明确显示“章节拓展”。
- 自动测试输出每章覆盖数和总覆盖数，最终必须为 57/57。

第一版 20 道完整实践继续保留并校正 4 个非权威标签；对剩余 19 个节点新增轻量实践。轻量实践仍需满足完整字段要求，不以“阅读资料”“思考一下”代替操作。

## 页面设计

### 动手实践页

`frontend/hands-on/index.html` 继续采用纯静态、无依赖实现：

- 顶部显示 57/57 节点覆盖状态，而不是只显示章节数。
- 章节导航支持 `#chN`，节点实践支持稳定的 `#task-id` 深链接。
- 每道题显示对应知识点标签、入口、步骤、成果、用时和验收判据。
- `chapter-extension` 题显示“章节拓展”而非知识点标签，不计入 57/57 节点覆盖统计。
- 外部工具入口明确标记“离开本站”，所有新窗口链接使用 `rel="noopener noreferrer"`。
- 加载 JSON 失败时显示可行动的错误提示，而不是空白区域。

### 章节页

修改 `scripts/build_frontend_demo.py` 的章节生成逻辑：

- 为每个知识卡片追加“去做实践”链接，目标为 `/hands-on/#task-id`。
- 链接由实践数据构建映射，不在生成器里手写 57 条条件分支。
- 若某节点没有实践，生成过程直接失败；不生成看似正常但入口缺失的页面。
- 重新生成 `frontend/chapter/1..10/index.html`，保证源逻辑与产物同步。

### 新手页

`frontend/beginner/index.html` 覆盖六类入口：

1. 豆包：中文对话、写作和日常解释。
2. ChatGPT：通用对话、写作、研究与多模态任务；当前网络无法验证时明确标注。
3. 文心千帆：百度云模型 API 与开发者工作台，使用当前有效产品入口，不使用已失效的旧文心一言网址。
4. 扣子：低代码智能体与知识库搭建。
5. 阿里云百炼：模型 API、调用监控与成本观察。
6. AI Master：讲解通关、独立测验和学习证据。

每张卡必须包含：

- 原创内联 SVG 流程图，只画通用任务流程，不复刻品牌 Logo。
- 适用场景。
- 核心功能。
- 三步上手路径。
- 登录、费用、网络或密钥门槛。
- 官方入口与核实状态。
- 不适合使用的情况，帮助新手避免选错工具。

页面顶部提供按目标选择的最短路径：“先问清楚”“先写出来”“先搭助手”“先调 API”“先验证自己是否真的懂”。

## 提示词协作规则

该要求属于用户与助手的长期协作协议，不在前端伪造一个“自动生成器”。写入长期记忆后，后续收到“场景 + 目的”时自动输出：

- 场景理解与补全假设。
- 通用版提示词：跨平台、低门槛、可直接复制。
- 高阶版提示词：角色链、输入契约、规则优先级、失败处理和自检。
- 豆包 / ChatGPT / 文心千帆适配说明。
- 待核实项与验证方法。

涉及事实、数据、引用或外部平台能力时，不把推测写成已实现能力。

## 原创性与软著边界

- 外部项目只记录仓库名、星标时点和抽象教学模式。
- 不复制外部 README、作业题、代码样例、CSS、图标或插图。
- 不引入新的第三方前端依赖。
- 新图解使用项目自行编写的 SVG 基础图形和文字。
- Git 提交信息区分“调研结论”“原创实现”“验证证据”，便于后续说明独立创作过程。
