AI Agent 的基本概念与组成

什么是 AI Agent

AI Agent 是一种能够感知环境、自主规划、调用工具执行行动、并根据结果反思调整的智能体。与传统的单轮问答不同，Agent 可以在没有人类逐步指令的情况下，自主完成多步骤复杂任务。

Agent 五大核心组件

组件职责典型实现
感知（Perception）接收用户输入和环境反馈文本输入、工具返回值、传感器数据
规划（Planning）分解目标为可执行的子步骤LLM 推理、Chain-of-Thought、任务树
记忆（Memory）存储历史信息和当前状态短期对话历史、长期向量库、工作记忆
行动（Action）调用工具与外部世界交互函数调用、API 请求、文件操作
反思（Reflection）评估结果并决定下一步自检、重试、调整策略

ReAct 模式

ReAct（Reasoning + Acting）是目前最主流的 Agent 运行范式，核心是推理与行动交替循环：

Thought（思考）：我需要先查天气，再决定带不带伞
Action（行动）：调用 get_weather(city="北京")
Observation（观察）：返回"北京，晴，25°C"
Thought（思考）：天气晴，不需要带伞
Final Answer（最终回答）：北京今天晴，建议不带伞

每一步的 Thought 让 Agent 的决策过程可解释、可审计，避免黑箱式的工具调用。

02

工具调用与函数执行

Tool Use 完整流程

1. 工具定义（Tool Definition）
   ↓ 向 LLM 描述工具的 name、description、parameters(JSON Schema)
2. 意图识别（Intent Recognition）
   ↓ LLM 判断是否需要调用工具、调用哪个工具
3. 参数提取（Argument Extraction）
   ↓ LLM 输出结构化的工具调用参数
4. 工具执行（Tool Execution）
   ↓ 程序根据名称匹配并调用对应函数
5. 结果回传（Result Return）
   ↓ 将工具返回值作为新的上下文交给 LLM
6. 后续决策（Next Decision）
   ↓ LLM 根据结果决定继续调用或给出最终回答

常见工具类型

  • 检索类：搜索引擎、向量数据库查询、知识库检索
  • 计算类：计算器、代码解释器、公式求值
  • 操作类：文件读写、数据库操作、API 调用
  • 通信类：发送邮件、调用 Webhook、推送通知

工具设计要点

  • 单一职责：每个工具只做一件事，描述清晰无歧义
  • 参数校验：对 LLM 生成的参数做类型和范围校验，不可信
  • 错误处理：工具失败时返回结构化错误信息，供 LLM 决策重试或换路径
  • 幂等设计：写操作尽量幂等，避免重复调用导致副作用
  • 超时控制：每个工具设置最大执行时间，防止卡死 Agent 循环

03

多智能体协作与安全边界

多智能体协作模式

模式结构适用场景
主从模式一个 Planner 分配任务给多个 Worker任务可明确分解、各子任务独立
辩论模式多个 Agent 对同一问题给出方案并互相评审需要多角度论证、降低单点偏见
流水线模式Agent A 的输出是 Agent B 的输入有明确先后依赖的处理流程
黑板模式所有 Agent 共享一个公共状态空间，各自读写复杂问题求解、各 Agent 关注点不同

三大安全风险与防护

1. 提示注入（Prompt Injection）

风险：用户输入或工具返回的内容中包含"忽略之前指令"等攻击文本，劫持 Agent 行为。

防护：

  • 将不可信输入与系统指令物理隔离，用明确的分隔符和角色标记
  • 对工具返回值做净化和转义，不直接拼入系统提示词
  • 关键操作（转账、删除）要求二次确认，不允许仅靠 LLM 判断

2. 权限越界（Privilege Escalation）

风险：Agent 通过工具调用获得超出预期的权限，如读敏感文件、执行系统命令。

防护：

  • 遵循最小权限原则，每个工具只授予完成任务所需的最低权限
  • 在沙箱中执行代码和命令，限制文件系统和网络访问
  • 敏感操作加审批闸门，高风险操作必须人工确认

3. 工具滥用（Tool Abuse）

风险：Agent 在错误推理下重复调用工具、调用错误工具，或被诱导执行破坏性操作。

防护：

  • 设置最大循环次数和单次任务超时，防止死循环
  • 维护工具调用白名单，未授权工具一律拒绝
  • 记录完整的审计日志：谁、在何时、调用了什么工具、参数是什么
