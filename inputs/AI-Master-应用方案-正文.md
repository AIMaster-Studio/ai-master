# AI Master — iCAN 应用方案

## 一、项目定位

AI Master 是面向学习大模型与 RAG 入门知识的大学生的学习原型。我们关注一个具体问题：学习者看完教程，常常还说不清概念，也无法判断自己能否运用。AI 对话可以给出流畅答案，但替学习者说出答案，并不等于学习者已经学会。

因此，我们把本次创新集中在"讲解通关"：学习之后先自己解释，再接受客观题验收，留下可以回看和复习的记录。

## 二、核心功能

### 1. 学习工作台
- 10 个章节、57 个课程节点
- 7 个核心模块进入通关流程
- 基础诊断、目标设定、节奏控制
- 认知地图为每个节点标明目标、任务和需要收集的证据

### 2. 双重验收机制

**讲解验收：**
- 学习者必须用自己的话解释关键概念
- 系统先进行七项完整性筛查（本地规则）
- 配置模型后可增加结构化复评
- 输入过短或重复关键词不能通过

**客观题验收：**
- 按预设正确答案独立判分
- 至少达到 75% 正确率
- 讲解和客观题都满足才记录通关
- 模型不能直接修改客观题答案

### 3. 学习记录与复习
- 本机 SQLite 或远程 Turso 双模式存储
- 刷新后可继续学习进度
- 错题记录和复习安排
- 可导出学习记录
- 间隔复习功能

### 4. 视觉陪伴
- 鲸鱼娘响应学习状态
- 学习陪伴与状态反馈
- 保留第三方原形象和已有动作

## 三、技术实现

### 架构
- Node.js 本机服务
- SQLite 本地存储 + Turso 远程持久化
- 前端：静态课程 + Three.js 星海 + Electron 入口

### AI 能力边界
- 讲解复评：本地规则（七项筛查）+ 可选模型复评
- 模型失败时明确降级，标记"本地练习"或"fallback-local"
- 推理模型需 4096 max_tokens 与 60s 超时
- 失败时明确拒绝而非自动通关

### 自测数据
- 21 组双盲测试准确率：90.4762%（混淆矩阵：TP8/FP0/TN11/FN2）
- 零假阳性
- 测试口径：deepseek-v4-pro
- 线上实际使用：deepseek-flash

## 四、创新性

### 与竞品的差异
1. **输出验收**：强制学习者用自己的话讲解，本地筛查 + 可选 AI 复评
2. **进度闸门**：讲解通过 + 客观题 75%，两者都满足才通关
3. **本机可演示**：开源 MIT，未配置模型时可走本地练习路径

### 不是什么
- 不是新基础模型
- 不是仅凭新教学术语的创新
- 不是完整商业化平台
- 不能声称所有素材为团队原创

## 五、诚实边界（必须原样保留）

1. **课程覆盖**：57 个课程节点，正文与考核覆盖情况逐项标注；不能说"五十七个知识点全部完整、全部掌握"
2. **AI 能力**：规则与可选模型提供练习反馈，存在误判，另设独立客观题；不能说"AI 精准判断学生真正理解"
3. **素材版权**：代码 MIT，但 dsh-pet 素材上游 README 写明禁止商用；不能声称"所有素材 MIT，可放心商用"或"原创鲸鱼娘"
4. **效果数据**：尚无本项目教育效果数据，已有研究计划；不能说"学习效果提高某个百分比"

## 六、应用前景

### 高校 B 端（主路径）
- 7 个核心模块的课程实践包
- 讲解验收流程 + 基础学习记录
- 按院系或课程授权的年费制
- 后续评估：教师班级视图、概念错因汇总

### 企业 B 端（次路径）
- 定制课程任务
- 私有部署方案
- 企业内部知识库 RAG 实验环境（规划中）

### C 端长尾
- MIT 代码核心 + 本地练习
- 免费核心 + 付费内容/部署/支持
- 用户自带合规 API 配置

## 七、验证计划

### 可用性验证
- 学生能否独立完成任务
- 能否理解反馈并找到复习入口
- 通过试点观察

### 效果验证
- 相同内容、相同学习时间下
- 讲解通关是否改善迁移任务与延迟测验表现
- 需要前测、平行题、盲评和预先确定的分析方案

## 八、团队分工与合规

### 资产边界
- 原有课程、Three.js 星海、Electron 入口是已有基础
- 本次工作：组织讲解、确定判题、持久记录，形成可检查的学习流程
- 鲸鱼娘：保留第三方来源，上游代码 MIT 但素材禁商用

### 合规声明
- 所有模型密钥通过环境变量注入，代码中无硬编码
- 学习记录可存本机 SQLite 或远程 Turso
- 开启远程模型后相关输入会发往服务商
- 商业化需要先完成素材授权核查
